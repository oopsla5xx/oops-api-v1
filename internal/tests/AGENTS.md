# AGENTS.md — internal/tests

Guide for AI agents writing tests in this repository.

---

## Workflow: writing tests for a new module

```
1. Write unit tests for any shared packages touched by the module
2. Write unit tests for application/query and application/command (using mocks)
3. Write integration tests for interface/handler (using NewTestDB)
4. Run: go test ./internal/modules/<name>/... -v
5. Run: make test-cover to check coverage
```

---

## Available helpers

### `tests.NewTestDB(t)`
Returns a pgxpool connected to the test database. Auto-skips if `DATABASE_DSN` is not set, so unit tests run without a database.

```go
pool := tests.NewTestDB(t)
```

### `tests.Truncate(t, pool, "table1", "table2")`
Truncates rows and resets sequences. Call inside `t.Cleanup` to isolate test state between runs.

```go
t.Cleanup(func() { tests.Truncate(t, pool, "users") })
```

### `factory.Seed(n)` — call in `TestMain` when deterministic data is required

```go
func TestMain(m *testing.M) {
    factory.Seed(42)
    m.Run()
}
```

## Conventions

### Package declaration
Always use the external test package:
```go
package user_test   // NOT package user
```

### Test naming
Table-driven with `t.Run` and English behavior descriptions:
```go
func TestCreateUser(t *testing.T) {
    tests := []struct {
        name    string
        input   ...
        want    ...
        wantErr bool
    }{
        {name: "creates user with valid email", ...},
        {name: "returns error when email already exists", ...},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            ...
        })
    }
}
```

### Assertions
```go
assert.Equal(t, want, got)   // soft — test continues after failure
require.NoError(t, err)      // hard — stops immediately on failure
require.Equal(t, want, got)  // use when subsequent assertions depend on this value
```

### Mocks (testify/mock + mockery)
Mocks are generated by `make generate` and live at `<module>/domain/mocks/`.

```go
repo := mocks.NewMockUserRepository(t)
repo.EXPECT().FindByID(ctx, userID).Return(user, nil)
```

### Integration test pattern (handler)
```go
func TestHandler_CreateUser(t *testing.T) {
    pool := tests.NewTestDB(t)
    t.Cleanup(func() { tests.Truncate(t, pool, "users") })

    gin.SetMode(gin.TestMode)
    r := gin.New()
    // wire handler...

    w := httptest.NewRecorder()
    req, _ := http.NewRequest(http.MethodPost, "/users", body)
    r.ServeHTTP(w, req)

    assert.Equal(t, http.StatusCreated, w.Code)
}
```

## Anti-patterns — never do these

```go
// ❌ Same-package test
package user

// ❌ Multiple separate Test functions instead of table-driven
func TestCreateUser_WithValidEmail(t *testing.T) {}
func TestCreateUser_WithInvalidEmail(t *testing.T) {}

// ❌ Fixing the assertion to match wrong output instead of fixing the code
assert.Equal(t, "wrong result", got)

// ❌ Missing cleanup between integration tests — causes state leak
pool := tests.NewTestDB(t)
// missing: t.Cleanup(func() { tests.Truncate(...) })

// ❌ Mocking the repository in a handler integration test
// Handler tests must use a real DB via tests.NewTestDB

// ❌ Hardcoding values instead of using the factory
input := CreateUserInput{Email: "user@example.com"} // use factory.NewUser() instead
```

## Coverage
- **CI fails** if total coverage < **90%**
- **Warning** (no fail) if any package < **80%**
- Excluded: `docs/`, `internal/infrastructure/database/sqlc/`, `cmd/api/`
